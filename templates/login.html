🔐 Authentication Bypass Lab

🟡 Difficulty : Medium

Category : Authentication

OWASP : A07:2021 Identification and Authentication Failures

Description

Authentication bypass vulnerabilities occur when an application incorrectly verifies user credentials or allows authentication controls to be circumvented.

In this lab, the login functionality contains an intentionally vulnerable SQL query.

Objective

Analyze the authentication mechanism and understand how improper handling of user input can cause the application to authenticate a user without properly validating the password.

Lab Concept

The vulnerable application builds its authentication query using user-controlled input. 

SELECT * FROM users
WHERE username = 'USER_INPUT'

The application then checks whether a database record is returned. The password is not incorporated into the SQL query used for authentication.

Test Environment

This lab is intentionally vulnerable and is designed to be tested only against your local VulnLab instance.

Example test input: 

' OR 1=1--

The purpose is to understand how SQL injection can affect an authentication decision.

How It Works

The vulnerable backend uses the supplied username directly inside an SQL statement. 

query = f"""
SELECT * FROM users
WHERE username = '{username}'
"""

If the resulting query returns a database record, the application creates a session for the supplied user.

Secure Version

query = """
SELECT id, username, password_hash
FROM users
WHERE username = ?
"""

result = cursor.execute(
    query,
    (username,)
).fetchone()

if result:

    # Verify the submitted password
    # against the stored password hash.

    authenticate_user()

else:

    message = "Invalid credentials"

Remediation

  • Use parameterized database queries.
  • Verify both username and password.
  • Store passwords using strong password hashing.
  • Do not build authentication queries using string concatenation.
  • Implement appropriate session management.
  • Avoid exposing database errors to users.
